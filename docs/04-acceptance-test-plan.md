# 验收与测试方案

版本：0.1
日期：2026-11-23

## 1. 目的

在正式开发前和发布前验证三个核心风险：

1. 系统能否可靠读取理工科资料中的文字、公式、图片和代码。
2. AI 能否稳定输出符合数据契约的知识图谱、命题画像和试卷。
3. 用户能否完成从资料到复盘的闭环，并理解哪些内容需要核验。

测试课程：

- 线性代数
- 大学物理
- 面向对象程序设计

## 2. 测试分层

### T1 文档解析

验证文件结构、文字、公式、图片、代码和位置引用。

### T2 数据契约

验证 AI 输出能通过结构、引用和分值约束。

### T3 生成质量

人工评估知识点覆盖、题目正确性、解析质量和来源依据。

### T4 端到端流程

从创建课程到生成复盘建议完整执行。

### T5 隐私与安全

验证本地数据、API Key、删除行为和不可信文档输入。

## 3. 测试资料要求

每门课程放在 `local-samples/<course>/`，至少包含：

- `slides.pdf` 或 `slides.pptx`
- `exam-paper.png` 或 `exam-paper.jpg`
- `expected-notes.md`

`expected-notes.md` 至少写明 3 到 5 个必须识别出的知识点。真实文件不得提交到公开仓库。

### 3.1 线性代数

建议覆盖：

- 矩阵运算
- 行列式或秩
- 线性方程组
- 向量空间或线性相关
- 特征值与特征向量

重点检查：

- 上下标、矩阵、分块和 LaTeX 是否保留
- 计算题参考答案步骤是否完整
- 证明题是否提供可自评的评分点
- 公式图片是否被静默删除

### 3.2 大学物理

建议覆盖：

- 核心公式及适用条件
- 单位与量纲
- 示意图或受力图
- 综合计算
- 实验数据处理或误差分析

重点检查：

- 公式、单位和图是否出现在同一题目上下文
- 图片是否保持正确页序
- AI 是否在缺少条件时擅自补条件
- 实验分析题是否给出评分点而非单一答案

### 3.3 面向对象程序设计

当前样例课程语境为 C++/MFC。

建议覆盖：

- 类与对象
- 封装、继承和多态
- 构造与析构
- 接口或抽象类
- 代码阅读和程序输出
- MFC 消息响应、对话框和组件绑定

重点检查：

- 代码缩进、符号和语言标识是否保留
- 生成题目是否使用 C++/MFC 语境，而不是错误假定为 Python
- 题目是否依赖未提供的代码
- 代码阅读题答案是否与上下文一致
- 设计题评分点是否可操作
- 不要求程序真正运行代码

## 4. 文档解析验收标准

### 4.1 通用

- 数字版 PDF、PPTX、DOCX 的核心正文提取覆盖率不低于 90%。
- 页码或幻灯片编号能够被定位。
- 空页、扫描页和乱码页必须进入警告列表。
- 图片和公式图片不能在没有警告的情况下丢失。
- 同一文件重复上传时能提示或复用缓存。

### 4.2 公式

- 样品中的关键公式必须可见，或被标记为图片/待校对。
- LaTeX 内容在前端正确渲染。
- 无法识别时不能返回看似正确但语义错误的公式。

### 4.3 代码

- 代码块保留缩进、换行和符号。
- 代码语言可以渲染为语法高亮。
- 扫描成图片的代码必须提示需要视觉模型或 OCR。

### 4.4 图片真题

- 能提取题型和分值。
- 不能确定的区域必须列入 `uncertainties`。
- 用户修正后才能把命题画像用于出卷。
- 关键分值与原图不一致时，测试判定失败。

## 5. 数据契约验收标准

以下项目必须达到 100%：

- 所有生成结果通过 JSON 结构校验。
- 每套试卷总分等于蓝图总分。
- 每个分区题量和单题分值乘积正确。
- 每道题有答案、解析或评分点。
- 每个 sourced 知识节点至少关联一条有效来源。
- 不存在的文件和页码不能作为有效来源。
- 已开始的作答绑定不可变试卷版本。

## 6. 生成质量验收标准

人工评分使用 1 到 5 分：

- 1 分：严重错误或无法使用
- 2 分：有明显缺失
- 3 分：基本可用，需要较多修改
- 4 分：质量良好，少量修改
- 5 分：可直接用于复习

发布前最低要求：

| 项目 | 最低标准 |
| --- | --- |
| 关键知识点覆盖 | 每门课 `expected-notes.md` 中至少 80% 被覆盖 |
| 来源准确性 | 抽样知识点中不得出现伪造页码 |
| 试卷结构 | 100% 符合蓝图 |
| 题目答案正确性 | 抽样题目中至少 90% 经人工确认无明显错误 |
| 解析完整性 | 客观题解析必须回答“为什么”，不能只重复答案 |
| 补充内容标记 | 无法从资料确认的内容 100% 标记 |
| 复盘关联 | 每个薄弱知识点可以回到图谱节点和来源 |

题目正确性低于门槛时，不得以“AI 模拟题”为由隐藏错误。需要在界面显示抽检和核验提醒。

## 7. 端到端验收脚本

### 7.1 主链路

1. 配置一个文本模型。
2. 创建“线性代数”课程。
3. 上传含多个公式的 PDF 或 PPTX。
4. 查看解析结果并修正至少一处识别错误。
5. 生成 30 分钟知识图谱。
6. 打开一个节点，跳转到对应页码。
7. 上传一张真题图片，确认视觉模型能力。
8. 修正命题画像中的题型或分值。
9. 设置 100 分、90 分钟的考试蓝图。
10. 生成试卷，确认分值总和。
11. 在线作答并交卷。
12. 完成主观题评分点自评。
13. 查看薄弱点和下一轮复习建议。
14. 将一道题加入错题本并重新练习。
15. 重启应用，确认历史和错题仍然存在。

### 7.2 异常链路

1. 上传损坏文件，确认失败状态明确。
2. 使用不支持图片的文本模型上传真题，确认阻止或提示 OCR 降级。
3. 模拟模型超时，确认可重试且不丢失原始资料。
4. 模拟 AI 返回错误总分，确认本地校验拦截。
5. 模拟 AI 引用不存在的页码，确认校验失败。
6. 在文档中加入提示注入文本，确认系统没有泄露 Key 或跳过规则。
7. 删除课程，确认文件、历史、错题和引用均不可访问。

## 8. 隐私与安全测试

- API Key 不出现在浏览器 DOM、导出文件、日志和错误信息中。
- 上传文件不离开本机，除非用户主动调用模型。
- 调用外部模型前，界面说明资料会发送给所选服务商。
- 删除课程后，本地文件存储和数据库中无残留业务数据。
- 模型输出中的 HTML、脚本和链接按不可信内容处理。
- 文档中的指令不能被当作系统指令执行。
- 本地服务默认只监听环回地址，不暴露到局域网。

## 9. 性能与稳定性目标

作为验证目标而非硬性营销指标：

- 30 页以内数字版课件解析反馈在 30 秒内出现进度。
- 解析和生成均有明确阶段状态。
- 单个长任务失败不导致已上传资料丢失。
- 作答自动保存失败时明显提示，不显示“已保存”。
- 10 万字以内的资料能完成分块、引用和缓存。

AI 服务延迟由用户选择的模型决定，产品不能以固定完成时间承诺。

## 10. 无障碍与适配

- 主要操作可通过键盘完成。
- 颜色之外还有文本或图标表示正确、错误和警告。
- 公式提供可复制的 LaTeX 源文本。
- 图片有替代文本；无法生成时明确标记。
- 手机宽度下作答页无需横向滚动即可完成选择题和文本输入。
- 关系图视图不影响大纲和清单视图中的同等信息访问。

## 11. 停止发布条件

出现以下任一情况时停止发布：

- 试卷分值校验会发生误放行。
- API Key 进入日志、导出文件或模型提示词。
- 解析失败页面被标记为已成功。
- 知识节点伪造不存在的来源。
- 已开始的试卷被后台重新生成覆盖。
- 删除课程后仍能从历史入口打开原资料。
- 三门验证课程中任一课程无法完成主链路。

## 12. 当前测试阻塞项

尚未提供三门课程的真实或公开样例资料，因此目前只能进行结构设计和合成数据测试。真实资料解析与生成质量验证必须等待样例到位。
