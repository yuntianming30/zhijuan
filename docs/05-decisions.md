# 决策记录与待确认事项

版本：0.1
日期：2026-11-23

## 1. 已确认决策

### D-001 首批用户

首批用户为理工科大学生，优先覆盖期末考试复习场景。

### D-002 首版验证课程

使用以下三门课程验证公式、图表和代码内容：

- 线性代数
- 大学物理
- 面向对象程序设计

它们是测试集，不是产品功能白名单。

### D-003 模型费用

首版采用用户自带模型 Key。项目方不提供公共 AI 额度池。

### D-004 产品形态

首版采用本地优先网页应用。暂不做小程序和云账号同步。

### D-005 生成方式

AI 输出结构化数据，由产品模板渲染页面。AI 不直接生成任意 HTML。

### D-006 内容范围

采用通用理工科知识对象和可配置题型，不为每门课程复制一套引擎。

### D-007 真题使用

真题图片默认用于提取命题结构和知识分布，不默认逐题复刻原题。

### D-008 判分范围

客观题自动判分。计算、证明、简答和程序设计题使用评分点自评。首版不执行用户代码。

### D-009 代码课程语境

面向对象课程必须读取或配置编程语言与框架。首轮真实样例为 C++/MFC，不能默认按 Python 生成代码和术语。

### D-010 DeepSeek V4 双模型

首版默认 DeepSeek 配置：

- 文本与推理：`deepseek-v4-pro`
- 图像与公式：`deepseek-flash`
- Base URL：`https://api.deepseek.com`

两个模型共用用户提供的 DeepSeek API Key。模型名称允许用户覆盖。

### D-011 结构化任务的思考模式

知识图谱、命题画像和固定 JSON 结构提取默认关闭 DeepSeek thinking，避免 reasoning token 占满输出预算。复杂综合出题可按需启用低强度思考。

### D-012 模块一本地闭环

首版模块一采用 React 页面加本地 FastAPI：

- 浏览器不直接持有 API Key
- 文件解析和模型调用在本地后端完成
- 上传文件和生成记录保存在 Git 忽略目录
- 最近一次知识图谱保存在浏览器本地
- 模块二模拟考试尚未接入

### D-013 模块二考试闭环

首版模拟考试采用：

- 可编辑的题型、题量、分值和难度蓝图
- `deepseek-v4-pro` 根据当前知识图谱出卷
- 出卷后强制校验题型、题量和总分
- 在线计时作答与题号导航
- 客观题自动判分
- 主观题按评分点自评
- 结果映射回知识节点，生成薄弱知识点和下一步建议
- 最近试卷、考试记录和错题 ID 保存到本地

当前不运行代码，不自动批改程序设计和证明题。

### D-014 真题画像与评分组

历年真题图片通过 `deepseek-flash` 提取为可编辑命题画像。题区支持 `scoringGroups`，可表达“一个大题内包含 9 分和 5 分两个小问”等结构。

当模型返回的卷面总分与题区分值合计不一致时，以已校验的题区分项合计为准，并把矛盾写入 uncertainties，不能静默修正。

### D-015 公式与课程切换

- KaTeX 统一覆盖到 0.19.1，依赖审计为 0。
- 同时识别 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 数学分隔符。
- 课程知识图谱按课程分别保存在浏览器本地。
- 首版课程切换开放面向对象程序设计和线性代数；大学物理样例暂未接入。

### D-016 模型 JSON 修复

DeepSeek 在输出 LaTeX 时可能产生非法 JSON 反斜杠。首版在严格 `json.loads` 失败后使用 `json-repair` 恢复结构化响应，再继续执行本地业务校验。修复器不能绕过分值、知识点和评分组校验。

### D-017 用户模型配置

设置页支持用户保存自己的 DeepSeek Key：

- 浏览器不保存完整 Key
- 环境变量优先于页面保存
- 本地配置位于 Git 忽略目录
- 支持连接测试、替换和删除

### D-018 开源发布方式

- 许可证：MIT
- 本地开发：`npm run dev:api` + `npm run dev`
- 自托管：Docker Compose
- CI：前端构建、依赖审计和 Python 契约测试
- 用户资料和模型配置不进入 Git

## 2. 可调整的工作假设

### A-001 文件名与产品名

当前使用“理工科期末复习工作台”作为暂定名称，不阻塞需求和验证。

### A-002 文件格式

首版目标支持 PDF、PPTX、DOCX、MD、TXT、PNG、JPG 和 WebP。真实支持程度以解析测试结果为准。

### A-003 本地存储

建议使用本地数据库保存结构数据，原始文件存于应用数据目录。具体数据库在技术验证后决定。

### A-004 模型接口

优先采用 OpenAI 兼容协议。支持预置服务商和自定义接口，实际名单在实现阶段确定。

### A-005 界面语言

首版界面以简体中文为主，数据结构预留多语言能力，不做完整国际化。

### A-006 浏览器范围

首版优先支持最新版 Chrome 和 Edge。Safari 和 Firefox 在 MVP 后补充验证。

## 3. 需要用户决定的事项

### Q-001 项目名称

选项：

- 保持描述型暂定名
- 使用独立品牌名
- 在技术验证后公开征名

已决定：使用“知卷 / ZhiJuan”，GitHub 仓库名使用 `zhijuan`。

### Q-002 开源许可证

选项：

- MIT：最宽松，便于个人和商业采用
- Apache-2.0：额外包含专利授权
- GPL-3.0：衍生项目也必须开源

已决定：采用 MIT。

### Q-003 用户如何启动应用

选项：

- 开发者启动：下载代码后执行命令
- 图形安装包：封装为桌面应用
- Docker 启动：适合熟悉容器的用户

已决定：首版提供开发者命令启动和 Docker Compose 自托管。图形安装包延后。

### Q-004 真题是否允许原题复现

当前假设为仅提取命题画像。若用户明确要求原题复现，需要增加版权提示、来源确认和非默认开关。

建议：保持当前决策，不默认复刻原题。

### Q-005 公共演示站

当前假设首版不提供公共演示站。后续可以提供只含合成资料的演示模式，避免承担 AI 调用成本和真实资料存储责任。

### Q-006 首个真实验证模型

已确认使用 DeepSeek V4 双模型方案，真实验证结果见 `07-deepseek-validation-report.md`。

不需要在聊天中提供 API Key。Key 应由后续本地配置界面或环境变量安全保存。

## 4. 下一个硬性依赖

真实资料验证需要三门课程的脱敏样例。缺少样例时可以继续开发数据契约和界面原型，但不能宣称解析能力已验证，也不能进入公开发布。

建议首批样例：

- 线性代数：含矩阵和公式的 PDF/PPTX，加一张真题图片
- 大学物理：含示意图、公式和单位的 PDF/PPTX，加一张真题图片
- 面向对象程序设计：含代码和类关系的 PDF/PPTX，加一张真题图片

每门课附带 3 到 5 个必须识别知识点的 `expected-notes.md`。
