# MVP 产品需求

版本：0.1
日期：2026-11-23

## 1. MVP 目标

完成一条可验证的纵向链路：

`课程 -> 资料解析 -> 知识图谱 -> 考试蓝图 -> 模拟试卷 -> 作答 -> 复盘`

MVP 不是两个独立的“导图生成器”和“试卷生成器”。所有产物都必须归属到课程，并保留来源关系和版本。

## 2. 用户角色

首版只有一个本地用户角色，不区分管理员、教师和学生账号。

用户需要拥有：

- 本地浏览器
- 可用的 OpenAI 兼容模型 API
- 可选的多模态模型 API

## 3. 功能需求

### FR-01 模型配置

优先级：P0

用户首次启动时进入模型配置：

- 选择服务商预设或“自定义 OpenAI 兼容接口”
- 填写接口地址、模型名称和 API Key
- 可选配置视觉模型
- 测试文本模型连接
- 测试视觉模型是否支持图片
- 选择是否使用本地 Ollama

要求：

- API Key 不进入 Git、日志、错误上报和生成内容。
- 未配置 Key 时可以使用内置演示数据，但必须明确标识。
- 连接失败时显示可操作的原因，不显示完整 Key。
- 模型能力显示为“文本”“视觉”“未知”，未知时在图片导入前提示。

### FR-02 课程工作台

优先级：P0

用户可以创建、重命名、归档和删除课程。

课程字段：

- 课程名称
- 学科类别
- 编程语言和框架，可选
- 课程说明
- 默认考试时长
- 默认总分
- 课程专属要求
- 创建和更新时间

提供“线性代数”“大学物理”“面向对象程序设计”三个空白预设，只影响默认提示词和题型建议，不限制内容。

对代码类课程，必须识别或由用户指定编程语言和框架。例如 C++/MFC 与 Python 的面向对象课程不能用同一套默认术语、代码风格和题型。

### FR-03 资料导入与解析

优先级：P0

支持批量导入：

| 格式 | MVP 要求 | 失败处理 |
| --- | --- | --- |
| 数字版 PDF | 提取文字、页码和图片 | 标记空页和乱码页 |
| 扫描版 PDF | 尝试 OCR 或视觉模型 | 无视觉能力时禁止静默生成 |
| PPTX | 提取文字、幻灯片编号、图片和代码块 | 标记公式图片 |
| DOCX | 提取标题、正文、表格和图片 | 保留基础层级 |
| MD/TXT | 直接读取并按标题分段 | 标记编码问题 |
| PNG/JPG/WebP | 作为图片资料或真题导入 | 提示视觉模型或 OCR 能力要求 |

解析结果必须：

- 显示总页数、成功页数、空页数、图片数和警告数。
- 允许用户预览并修正关键文字。
- 保留原文位置引用。
- 不把解析失败的页面当成已读取。
- 对公式和图表使用图片或结构化公式保存，避免静默删除。

### FR-04 知识图谱与重点梳理

优先级：P0

用户可选择：

- 复习深度：10 分钟速览、30 分钟复习、完整梳理
- 侧重点：全面覆盖、基础巩固、易错点、计算或证明、课程自定义
- 视图：大纲、关系图、重点清单

知识节点类型：

- 定义
- 定理或定律
- 公式
- 方法或步骤
- 实验
- 图表
- 代码概念或算法
- 典型例题
- 易错点

每个节点至少包含：

- 标题和简要解释
- 重要程度
- 节点类型
- 来源引用或“AI 补充”标记
- 与其他节点的关系

用户操作：

- 展开或折叠节点
- 查看原文出处
- 收藏节点
- 标记“已掌握”“仍需复习”
- 排除明显无关节点

### FR-05 真题命题画像

优先级：P0，条件性功能

用户可选择上传一张或多张图片格式的历年真题。

系统提取：

- 题型和题量
- 各题型分值
- 章节或知识点覆盖
- 难度分布
- 常见表述方式
- 重复出现的考点
- 无法识别的区域

要求：

- 先显示识别结果供用户修正，再进入考试蓝图。
- 默认只用于分析命题结构和风格，不逐题复刻原题。
- 用户未上传真题时，系统根据课件、课程预设和手动设置生成蓝图。
- 不得伪造真题中的章节或分值。

### FR-06 考试蓝图

优先级：P0

蓝图字段：

- 考试名称
- 时长
- 总分
- 题型分区
- 每区题目数量和单题分值
- 同一题区内不同分值的小问组
- 难度分布
- 章节或知识点覆盖比例
- 开卷或闭卷
- 是否参考真题风格
- 其他考试要求

本地校验：

- `题目数量 × 单题分值` 必须等于分区分值。
- 使用小问组时，各组题量乘单题分值必须等于该组总分，并与分区总分一致。
- 所有分区分值之和必须等于总分。
- 难度比例之和必须为 100%。
- 章节覆盖比例之和必须为 100%。
- 未通过校验时禁止生成试卷。

用户必须确认蓝图后才能出卷。

### FR-07 模拟试卷生成

优先级：P0

支持题型：

- 单选题
- 多选题
- 判断题
- 填空题
- 简答题
- 计算题
- 证明题
- 实验分析题
- 代码阅读题
- 代码补全题
- 程序设计题

每道题包含：

- 题干
- 题型
- 分值
- 所属知识点
- 参考答案
- 解析或评分点
- 来源依据
- 难度
- 判分方式：自动判分、评分点自评、人工评分

代码题的编程语言和框架必须继承自课程配置或本次明确指定，不得静默假定为 Python。

生成后执行本地结构校验：

- JSON 结构有效
- 题量和题型符合蓝图
- 分值完全一致
- 所有题目有答案或评分点
- 所有知识点引用有效

用户操作：

- 重新生成个别题目
- 替换题目
- 保存为新版本
- 开始作答
- 打印或导出为后续功能

### FR-08 在线作答

优先级：P0

作答页包含：

- 倒计时，可选择暂停规则
- 题号导航
- 已答、未答和标记状态
- 自动保存
- 提交前未答题提醒
- 作答结束后自动保存快照

判分：

- 客观题自动判分。
- 计算题、证明题和简答题显示评分点，由用户自评。
- 程序设计题默认只按评分点自评，不运行代码。
- 用户可以为错误标记原因：概念不清、公式遗忘、计算失误、审题错误、时间不足、其他。

### FR-09 结果复盘与下一轮复习

优先级：P0

结果页展示：

- 总分和题型得分
- 用时
- 正确率和未答题数
- 知识点掌握度
- 错题及对应原文
- 最需要优先复习的知识节点
- 下一轮 15 分钟、1 小时或完整复习建议

用户可以：

- 将错题加入错题本
- 收藏题目
- 创建新一套小规模强化练习
- 返回知识图谱查看薄弱节点

个性化建议必须基于本次答题数据，不能只重复课程摘要。

### FR-10 历史、错题与收藏

优先级：P0

历史记录：

- 按课程展示资料、知识图谱、试卷和作答记录
- 记录生成时间和模型名称
- 保留试卷快照，题目重新生成不覆盖旧作答

错题本：

- 按课程、知识点和错误原因筛选
- 保留原题、答案和解析快照
- 支持重新练习和标记已掌握

收藏：

- 可收藏知识点和题目
- 保存来源引用

### FR-11 本地数据管理

优先级：P0

设置页必须支持：

- 查看本地数据占用
- 导出课程数据
- 删除单份资料
- 删除整门课程及相关生成记录
- 清除全部本地数据
- 清除模型配置

删除操作必须二次确认，并明确说明会删除哪些数据。

## 4. 非功能要求

### 4.1 隐私与安全

- 默认不上传资料到项目作者服务器。
- 用户 API Key 不写入日志。
- 文档内容按不可信输入处理，防止文档中的提示注入改变系统规则。
- 模型输出按纯文本、Markdown、LaTeX 和代码渲染，不执行任意 HTML 或脚本。
- 图片、试卷和课程数据在删除后不能继续从历史入口访问。

### 4.2 可靠性

- 长任务展示进度和当前阶段。
- 模型超时或限流时可重试。
- 应用重启后恢复未完成任务或明确标记失败。
- 生成结果先保存原始响应，再进行结构解析，避免一次解析失败导致内容丢失。

### 4.3 可用性

- 桌面端为主要编辑环境。
- 作答页支持常见平板和手机宽度。
- 公式使用 LaTeX 渲染，代码有语法高亮。
- 颜色不能作为唯一状态标识。
- 所有破坏性操作有明确确认。

## 6. MVP 排除范围

- 用户注册和云同步
- 支付、额度和订阅
- 社交分享和公开题库
- 代码沙箱和自动编译运行
- 复杂图形自动绘制
- 移动端小程序
- 自动识别所有手写公式
- 完整学术引用规范

## 7. 发布前关卡

MVP 不得在以下任一条件未满足时发布：

- 三门验证课程无法完成基础链路。
- 试卷分值或题量不能稳定校验。
- 解析失败被当作成功。
- 资料型内容没有来源且未标记补充。
- API Key 可能进入日志或导出文件。
- 用户无法彻底删除本地课程数据。
