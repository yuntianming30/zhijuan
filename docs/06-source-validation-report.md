# 首轮真实资料验证报告

版本：0.1
日期：2026-11-23
数据范围：用户提供的脱敏课程资料

## 1. 结论

首轮资料足以继续推进产品验证，但不能把“文本提取成功”当作“内容可用”。

核心结论：

1. OOP 文字类复习 PDF 的原生文字和代码提取质量良好。
2. 线性代数 PPTX 大量使用 OLE 公式对象，359 张幻灯片中有 313 张需要视觉核验。
3. 大学物理 PDF 虽有文字层，但公式符号顺序不可靠，视觉页面必须保留。
4. 线性代数真题图片清晰，可人工确认 100 分、7 个题区的考试结构。
5. OOP 课程实际语境为 C++/MFC，不能默认使用 Python 或纯语言无关模板。
6. 首版必须支持逐页或逐幻灯片图像，并允许视觉模型读取；只做 PDF 文本抽取不足以支撑公式类课程。

## 3. 课程发现

### 3.1 线性代数

- 矩阵课件 248 张，向量组课件 111 张。
- 总字符量并不低，但公式通常被拆成大量离散符号。
- 含 OLE 对象的幻灯片可能没有任何可提取文字。例如矩阵综合例题页视觉内容完整，原始文字为空。
- Office 公式对象可提取部分字符，但不能可靠恢复矩阵结构、运算符顺序和分块关系。
- 通过 PowerPoint 导出 PDF 后，文本量增加，但公式仍可能出现阅读顺序错乱。

结论：

- 每张幻灯片必须能够按需渲染为图像。
- 公式语义应由视觉模型结合页面图像提取，并保留原图供校对。
- 普通文本和 Office 数学对象只能作为辅助输入。

### 3.2 大学物理

- 7 份课件覆盖电荷、电场、高斯定理、电势、导体与电介质、电容。
- 公式页含大量嵌入图片，文字层存在符号顺序错乱。
- 绝大多数页面不是纯扫描页，因此不能只根据“有文字”判断解析质量。
- 抽查发现同一例题中距离指数与后续代入值存在视觉不一致，生成内容时必须标记来源疑点，不能静默修正。

结论：

- 物理页需要文字、图片和版面同时参与解析。
- 公式必须保留适用条件和单位。
- 题解和推导需要“来源疑似错误”状态。

### 3.3 面向对象程序设计

- 资料格式为文字型 PDF，24 页均能提取原生文字。
- 内容包括题目、代码和正确答案，适合作为首批生成质量对照。
- 课程实际使用 C++/MFC，涉及对话框、按钮、定时器、消息响应和数据绑定。
- `UpdateData`、`CButton`、`OnBnClicked` 等模式说明不能使用通用 Python 示例代替。

结论：

- 课程模型必须记录编程语言和框架。
- 代码题需要语言感知的语法高亮和评分点。
- 代码执行仍然不属于首版范围。

## 5. 对首版架构的影响

### 5.1 解析结果必须同时保留文本与视觉页面

每个 PDF 页和 PPTX 幻灯片至少保留：

- 原始文字
- 页码或幻灯片编号
- 可用时的渲染图片
- 文字提取质量
- 是否疑似包含公式
- 是否需要视觉核验

### 5.2 视觉模型是公式课程的必要能力

当用户选择纯文本模型时：

- 可以处理 OOP 文字资料和结构较简单的文本课件。
- 必须提示公式类内容可能不准确。
- 不能把公式密集页面静默送入生成流程。

### 5.3 PPTX 需要分级支持

建议支持顺序：

1. 直接解析 PPTX 文本、图片、表格和 Office 数学对象。
2. Windows 且安装 PowerPoint 时，可选本地导出 PDF 和页面图片。
3. 其他环境建议用户导出 PDF 后再上传。
4. 未来可评估 LibreOffice headless 作为跨平台渲染器。

### 5.4 来源质量分为多级

- `nativeText`：原生文字基本可靠。
- `mixed`：文字可读但含公式或版式风险。
- `visualOnly`：几乎没有可用文字。
- `needsVisualReview`：PPTX 含公式、嵌入对象或近空白页。
- `sourceInconsistency`：来源内部存在疑似矛盾。

## 7. 下一步验证

真实 AI 能力验证还需要用户选择一个支持文本的模型，以及一个支持图片的视觉模型。测试时不得要求用户在聊天中提供 Key；应由应用或本地环境安全配置。

必须完成：

1. 用同一份线性代数真题图片提取命题画像，并与黄金画像比较。
2. 用矩阵公式页面测试视觉模型是否可以输出可渲染的 LaTeX。
3. 用大学物理公式页测试适用条件、单位和图示是否保留。
4. 用 C++/MFC 资料测试语言和框架是否被正确继承。
5. 比较纯文本模型与视觉模型在同一批任务上的差异。
