## 3. 物理公式页结果

输入为大学物理库仑定律例题页面。

模型正确完成：

- 识别 7 个可见公式
- 输出可渲染 LaTeX
- 区分静电力与万有引力
- 保留质量和单位
- 识别出距离指数与后续代入值存在矛盾
- 在 warnings 中要求以原图核对，没有自行掩盖问题

结论：`deepseek-flash` 能胜任公式页的第一轮结构化提取，但结果仍需原图对照和用户确认。

## 3.1 OOP 知识图谱结果

使用 5 份真实 OOP 复习资料，关闭思考模式后得到：

- 12 个知识节点
- 9 条关系
- 2 条易错提醒
- 所有 sourced 节点均通过文件 ID 和页码校验
- 正确识别 C++/MFC 语境
- 覆盖构造函数、访问控制、图形绘制、消息、定时器和组件绑定

首次调用时 `deepseek-v4-pro` 默认开启思考模式，6000 个输出 token 全部用于 reasoning，最终 `content` 为空且 `finish_reason=length`。

后续策略：

- 固定 JSON 结构任务默认 `thinking: {"type": "disabled"}`
- 复杂出题或疑难推断才启用低强度 reasoning
- 必须检查 `finish_reason` 和空内容

## 4. 线性代数真题结果

模型正确完成：

- 总分 100 分
- 选择题 5 题、每题 3 分、共 15 分
- 填空题 6 空、每空 3 分、共 18 分
- 第三大题 14 分，其中两个小问分别为 9 分和 5 分
- 第四、五、六题分别为 12、15、18 分
- 第七题证明题 8 分
- 未显示考试时长时返回 `null`
- 没有推测难度和完整答案

模型为了适配“每分区统一单题分值”的提示结构，把第三大题拆成了两个 section。总分和内容虽正确，但结构不符合原卷语义。

因此系统数据模型已改为支持 `scoringGroups`，允许同一个大题内存在不同分值的小问。

## 5. 模型能力结论

### 5.1 `deepseek-v4-pro`

适合：

- 知识图谱整理
- 重点清单
- 根据考试蓝图生成题目
- 解析和评分点生成
- 学习复盘

注意：

- 不支持图片输入
- 默认思考模式会消耗 reasoning tokens
- 必须限制输出 token 并校验是否被截断

### 5.2 `deepseek-flash`

适合：

- 公式页面识别
- 真题图片结构提取
- 图表、代码截图和扫描页转写
- 低置信度区域标记

注意：

- JSON 遵循并非 100% 稳定
- 整页图片会自动缩放
- 小字号公式仍可能需要局部裁剪
- 任何公式和分值都必须允许用户校对

## 6. 首版接入要求

1. 设置页采用 DeepSeek 预设自动填充两个模型名。
2. 文本和视觉模型分别测试连接。
3. 视觉提取结果先进入“待确认”状态。
4. 图片和公式节点保留原页定位。
5. 模型调用日志不得记录 API Key 和完整 Base64。
6. 所有结构化响应经过本地校验后才能进入下一步。
7. JSON 失败自动重试一次，仍失败则保存错误状态。
8. 大题支持多个不同分值的小问组。
9. 对来源矛盾设置独立警告，不允许模型静默修正。

## 8. 已完成的端到端闭环

本地 FastAPI 与 React 页面已经连通：

1. 页面读取本地 API 状态。
2. 用户点击“按当前范围重新梳理”使用 5 份样例资料重新生成。
3. 用户选择本地 PDF 后，文件进入解析、模型生成和结构校验。
4. 生成结果更新导图、复习重点、重要程度和来源页码。
5. 最近一次结果保存在浏览器本地。
6. 来源按钮可以打开对应页面的提取片段。

实测模型一次返回了 19 个知识节点，超过 8 到 14 个的约束。后端已增加本地限量逻辑，优先保证每个分支有一个节点，再按重要程度保留最多 14 个，并显示警告。

## 9. 模拟考试端到端结果

真实生成了一套 100 分、90 分钟的 C++/MFC 模拟卷：

- 单项选择题 10 题，每题 2 分
- 代码阅读题 4 题，每题 10 分
- 程序设计题 2 题，每题 20 分
- 共 16 题，总分 100
- 所有题目均关联知识节点并包含答案、解析或评分点

浏览器自动化完成了：

1. 从考试蓝图生成试卷。
2. 预览全部 16 题。
3. 进入计时作答并完成一题。
4. 交卷进入结果复盘。
5. 在桌面和手机视口检查蓝图、预览、作答和结果页面。

移动端复盘页曾出现 151px 横向溢出，原因是代码块的最小内容宽度撑开结果容器；已通过网格 `min-width: 0` 和代码块宽度约束修复。
